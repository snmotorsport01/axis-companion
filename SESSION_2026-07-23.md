## Firmware — `axis_can_monitor`

- **Version now: `v0.34.1`** (Config.h `FW_MAJOR/MINOR/PATCH = 0/34/1`, `BUILD_VERSION="v0.34.1"`).
- **v12 wire format (GaugeCfg 319 B)** = the whole v11 219-B struct UNCHANGED + an appended
  `uint16_t slotColor[GAUGE_PAGES][SLOTS_PER_PAGE]` (per-VALUE RGB565; 0 = fall back to arcColor).
  - Fully back-compat: `BleGaugeCfg.cpp` (ColorCb + CfgCb) + `App.cpp::prefsLoadCfg_` accept BOTH
    219 B (v11) and 319 B (v12). `CFG_BYTES_V11 = offsetof(GaugeCfg, slotColor)`. Old founder-gauge app + old NVS blobs still work.
  - `GaugeConfig.h`: `slotColour(g,p,s)` resolver. `ScreenGauge.cpp`: `SC(sc,i,fallback)` helper threaded
    through every renderer (bars slot0..3 · hero slot0/1 · needle/ticks slot0/1 · regent slot0 ·
    chrono slot0/1 · tuner band slot1). Slot 0 = the old single arc → un-recoloured gauge is pixel-identical.
- **Regent/Chrono**: removed the concentric-`fillCircle` centre heat-glow (banded on AMOLED) → flat face.

### ⚠️ OTA + iOS background reality
keep-awake stops AUTO-lock only. Added this session: `UIBackgroundModes:[bluetooth-central]`
(Info.plist), flash() timeout 8s→20s, windowed SYNC retries the batch on timeout (≤12).
**Hard iOS limit:** JS is SUSPENDED while the app is backgrounded, so a long app-switch still can't
progress — the link now survives a brief switch + resumes, but keeping the app foregrounded is most reliable.
