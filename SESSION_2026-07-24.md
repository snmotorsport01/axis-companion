## Detail

### Background + text (the long thread)
- `carbonWave.ts` `size()` uses the **viewport** (not `getBoundingClientRect`) + a rAF re-measure —
  root-cause fix for "waves only drew in the top band". Canvas is blurred directly
  (`.aeroflow{filter:blur(7px)}`), translucent panels show it through.
- **Text**: tried `mix-blend-mode:difference` (mid-tone grey wash — rejected) → white + crisp outline
  (blurry — rejected) → **final = darken the frost**. `.axisshell::after` veil now starts
  `rgba(8,10,13,.42)` even at the top so the moving sheen can't brighten the bg enough to wash text;
  text is plain solid white (`#f3f5f8`, dim tier `#c3c8cf`). **Tunable knob:** the `.42` top-veil alpha
  trades readability ↔ wave visibility.

### DTC card (matches founder-gauge)
- `dtcCard(r)` renders: code + severity pill (`--sv`), headline, `systemShort`, **Symptoms**, a
  full-bordered **drive-ability callout** (tinted by severity), **Most likely causes** (numbered gold
  discs), **What to check** (gold ✓), and a **Search more detail & videos ↗** button → `dtcSearch(code)`.
- All content from `dtcRich.ts`'s `richDtc(code)` — offline, every code gets a full card.

### Connect-flow bug fixes
- **`monitorCfg.ts:342`** decode clamp was `layout > Layout.TICKS ? HERO` — it rewrote premium
  TUNER/REGENT/CHRONO (4/5/6) to HERO on **every read**. Fixed to `> Layout.CHRONO`. (Encode/validate at
  line 393 was already correct; codec re-verified byte-for-byte, symmetric.)
- **Peak-alerts crash (HIGH):** `shown` included channel id 0 (NONE, an empty slot) and dereferenced
  `S.peaks[0]` (undefined) → `render()` TypeError on the first render after connecting a gauge whose page
  has an empty secondary slot. Fixed with `.filter(id => id && S.peaks[id])`.
- **Page persistence:** `S`/`S.pages` live inside `onMount`, so opening a Pro page (swaps `store.page`
  → shell unmounts) reset pages to factory. Now saved to `localStorage['axis.pages']` (`savePages()` on
  every mutation + `pullGaugeConfig`) and restored at init (premium faces re-unlocked; arrays padded to 5).

### Gauge brightness
- The **Screen-brightness slider** existed only in `MonitorConfig.svelte` (the pre-connect screen), so it
  was unreachable once connected. Added into **Looks → GAUGE** (below Peak alerts): `setBright(v)` →
  `mon.setBrightness(v)` live-dims the AMOLED + folds into `_gaugeCfg.brightness` for Save-all. `S.bright`
  captured from the gauge in `pullGaugeConfig`.

### Cleanup
- `Diagnostics.svelte` retitled **"Record log"**, Fault-codes card removed (DTC has its own tab), leads
  with **Drive log · data** + **Bus log · CAN capture**. Removed the now-dead `richCard` snippet,
  `deepDive`/`lookupDtc`/`readCarCodes`/`clearCarCodes`/`toRich` + their state, unused imports, dead CSS.

## 🛣️ Roadmap — DTC "Search more" → **bring-your-own AI agent**

**Decision (owner, 2026-07-24):** the DTC card's *"Search more detail & videos ↗"* should NOT stay a
web-search hand-off. Next step is an **AI diagnosis agent that the user connects their own AI to** — the
owner picks/authenticates an AI provider, and the card asks it about the specific code + live car context.

Direction / open questions to spec next:
- **Bring-your-own-AI (BYO-key):** a Settings screen where the user connects a provider they choose
  (e.g. Claude / OpenAI / Gemini / a local model) with their **own API key**, stored on-device. No SN
  backend cost, no shared key. The DTC card's button becomes **"Ask AXIS AI"** when a provider is connected
  (falls back to web search when none is).
- **Context to feed the model:** the code(s) + `richDtc` facts + live freeze-frame the gauge can read
  (RPM / coolant / load / MIL state) → a grounded, car-specific answer instead of a generic search.
- **Conversational:** follow-ups ("is it safe to drive to work?", "what part number for a V60 T8?"),
  the AI reasoning over the offline dictionary + live telemetry.
- **Privacy/compliance:** ★ never send VIN or GPS/location; key stays on-device; disclose that the code +
  car readings leave the phone to the user's chosen provider. Revisit `reference_snaxis_store_compliance`
  (App Privacy form) before shipping.
- **Where it fits:** builds on the existing `AI DTC agent` idea in the ecosystem roadmap + the DTC-strategy
  memory; this session pins the **user-selectable / BYO-AI** model specifically.
